# Как сделать сайт по шагам

Этот файл — **старт для новичка**. Мы собираем учебный интернет-магазин по шаблону **Coral** (файл `Coral.fig`): одежда и аксессуары, не туры.

Читайте сверху вниз. После каждого шага можно открыть готовую папку `stage-…` и сравнить со своей работой. Подробности и ссылки на теорию — в [guides/](guides/README.md), тесты — в [tests/](tests/README.md).

Как работать над каждым этапом (порядок действий, а не содержание) — [Методика пошагового выполнения](metodika-po-shagam.md).

---

## Что получится в конце

Сайт, который:

1. Показывает витрину как в макете.
2. Открывает окно входа и карточку товара.
3. Кладёт товар в корзину и оформляет заказ.
4. Пускает админа добавить новую карточку.

Сначала это просто страницы в браузере. Потом появляется «кухня»: сервер, база данных.

---

## Что нужно на компьютере

| Когда | Что |
| --- | --- |
| С первого дня | Браузер (Chrome, Edge, Firefox) и редактор кода (VS Code / Cursor) |
| С шага 5 | Python — чтобы поднять простой сервер: `python -m http.server 8080` |
| С шага 6 | Один из трёх: PHP **или** Node.js **или** Python+Django |

Первые шаги (HTML, CSS) открываются **двойным кликом** по `index.html`.  
С шага 5 так нельзя: браузер не отдаст файл `products.json` с диска. Нужен адрес вида `http://localhost:8080/`.

## Как устроены папки

Каждый шаг курса лежит отдельно, как фотография работы на этот день:

```
stage-01-html/          готовый HTML без красок
stage-02-css/           уже похоже на макет
stage-03-bem/           те же краски, аккуратные имена классов
…
stage-10-shop-admin/    корзина, заказы, админка
```

Можно **смотреть эталон** и параллельно собирать свой сайт в папке `site/`. Не обязательно писать всё с нуля, если преподаватель сказал «разберите готовую папку».

## Подразделы главной Coral (что за блоки)

Ниже — блоки макета **сверху вниз**. Комментарий к каждому: зачем он человеку, который зашёл в магазин. Когда будете верстать, идите в этом порядке.

### Шапка (поиск, логотип, Account, корзина)

Комментарий: это «пульт» сайта. Человек всегда видит, где он, как найти товар и как войти. Логотип ведёт на главную. Account — вход. Сумка — корзина.

В HTML это `<header>`.

### Меню каталога

Комментарий: список отделов магазина (украшения, одежда, дом…). Это не украшение, а навигация — тег `<nav>` и список ссылок.

### Герой (два фото + слово Collections + Shop now)

Комментарий: первый экран «продаёт настроение». Большой заголовок — один на страницу (`<h1>`). Кнопка Shop now не отправляет форму, а **переводит** к товарам — это ссылка `<a>`.

### Логотипы брендов

Комментарий: ряд марок. Человек быстро понимает, «это магазин известных брендов». Обычно простой список картинок.

### Категории (Explore new and popular styles)

Комментарий: крупные плитки (пальто, брюки…). Это витрина отделов, не конкретный артикул. Клик ведёт к сетке товаров.

### Сетка товаров (карточки)

Комментарий: сердце магазина. Одна карточка = один товар: фото, название, категория, цена, иногда бейдж Sale/Hot. В HTML карточка — `<article>`. Позже по клику откроется большое окно товара.

### Баннер (тёмный блок, Zara, 70%)

Комментарий: реклама коллекции. Не карточка товара, а акция: картинка + текст + ссылка «смотреть коллекцию».

### Best sellers (табы All / Dress / Bag…)

Комментарий: «что берут чаще». Табы — фильтр списка, не новые страницы. На узком экране список просто короче.

### Instagram

Комментарий: живые фото «как носят». Для курса это ряд картинок, без настоящей авторизации Instagram.

### Рассылка (email + Submit)

Комментарий: магазин просит почту ради скидок. Это **форма**: подпись, поле email, кнопка отправки. Пока сервера нет — форма может никуда не уходить, но разметка уже как у настоящей.

### Подвал (ссылки, соцсети, © Coral)

Комментарий: служебные ссылки и копирайт. Человек доскроллил вниз — здесь «о нас», доставка, контакты. Тег `<footer>`.

### Окно входа (в макете отдельного экрана нет)

Комментарий: мы **добавляем** его сами по цветам Coral. Зачем: без входа нельзя честно сказать «это моя корзина». Сначала рисуем окно, потом открываем скриптом, потом проверяем пароль на сервере.

### Окно карточки товара

Комментарий: крупное фото, цена, кнопка «в корзину» / «выбрать». Чтобы не прыгать на другую страницу на учебном этапе. Страница `product.html` — запасной путь без скриптов.

## Шаг 1. HTML — скелет страницы

Комментарий к шагу: собираем **смысл** без красок. Как каркас дома до обоев.

1. Создайте `index.html` с «шапкой документа»: doctype, язык, кодировка, title.
2. Разметьте шапку, меню, героя, категории, карточки, баннер, подвал тегами `header`, `nav`, `main`, `article`, `footer`.
3. У картинок напишите `alt` (что на фото).
4. У каждого поля формы — подпись `label`.
5. Ссылку «Shop now» сделайте `<a>`, кнопку «Submit» в форме — `<button>`.

Откройте файл в браузере. Будет «голое» — так и надо. Страница должна читаться списком заголовков.

Эталон: `stage-01-html/index.html`  
Подробнее: [guides/01-html.md](guides/01-html.md).  
Вводная лекция (семантика, формы, разбор теста): [lectures/01-html](lectures/01-html/README.md).

## Шаг 2. CSS — краски и сетка

Комментарий к шагу: натягиваем макет. Классы пока простые: `header`, `hero`, `btn`.

1. Подключите файл стилей и шрифты.
2. Цвета из макета положите в переменные `:root`.
3. Сверху вниз: шапка → герой → категории → карточки → баннер → подвал.
4. Шапка — в ряд (Flex). Карточки — сетка (Grid).

Откройте `stage-02-css/index.html`. Должно быть похоже на Figma на широком экране.

Подробнее: [guides/02-css.md](guides/02-css.md).  
Вводная лекция: [lectures/02-css](lectures/02-css/README.md).

## Шаг 3. БЭМ — имена классов

Комментарий к шагу: вид тот же, имена честные. Карточку можно перенести в другое место, стили не сломаются.

Пример имени: блок `product-card`, кусок внутри `product-card__price`, вариант `product-card__badge_type_sale`.

Скопируйте шаг 2 и переименуйте классы. Сравните с `stage-03-bem/`.

## Шаг 5. JavaScript — поведение

Комментарий к шагу: страница оживает. Товары берутся из файла `data/products.json`, окна открываются классом, форма проверяет email.

Обязательно локальный сервер:

```powershell
cd stage-05-js
python -m http.server 8080
```

Откройте http://localhost:8080/ (не двойной клик по файлу).

Должно быть: карточки появились, Esc закрывает окно, «выбрать» без входа просит Account.

Подробнее: [guides/05-js.md](guides/05-js.md).  
Вводная лекция: [lectures/05-js](lectures/05-js/README.md).

## Шаг 6. Сервер — общая кухня

Комментарий к шагу: данные и пароль живут не в браузере, а на сервере. Один договор (URL и JSON), три языка на выбор: PHP, Django или Node.js.

Запуск одного варианта (примеры):

```powershell
cd stage-06-server\nodejs
npm start
```

Сайт: http://localhost:8002/

Зарегистрируйтесь, откройте карточку, выберите товар, нажмите F5 — выбор не должен пропасть.

Подробнее: [guides/06-server.md](guides/06-server.md), прогон команд: [../../stage-06-server/TESTING.md](../../stage-06-server/TESTING.md).

## Шаг 10. Корзина, заказ, админка

Комментарий к шагу: это уже магазин. Покупатель кладёт в корзину и оформляет заказ. Админ добавляет новую карточку.

1. Запустите сервер из `stage-10-shop-admin/` (не из этапа 6).
2. Обычный пользователь: вход → Add to cart → страница Cart → Checkout → Orders.
3. Выйдите. Войдите: `admin@coral.local` / `admin123`.
4. Ссылка Admin → создайте товар → обновите витрину.

## Мини-словарь

| Слово | Простыми словами |
| --- | --- |
| HTML | Скелет: что заголовок, что ссылка, что картинка |
| CSS | Краски, сетка, шрифты |
| БЭМ | Правила имён классов, чтобы стили не путались |
| JavaScript | Поведение: клик, проверка формы, загрузка списка |
| API | Договор: какой адрес спросить и какой ответ придёт |
| Cookie / сессия | Сервер помнит, что вы вошли |
| База данных | Таблицы на диске: пользователи, товары, заказы |
| Админка | Страница для сотрудника магазина, не для покупателя |

## Если что-то не открывается

| Симптом | Что сделать |
| --- | --- |
| Карточки пустые, ошибка про JSON / fetch | Открывайте через `http://localhost:…`, не файл с диска |
| `php` не является командой | PHP не установлен или нужен **новый** терминал после установки |
| Регистрация «Invalid data» в curl из PowerShell | Тело запроса пишите в `.json` файл, не в кавычки `-d "{...}"` |
| Картинки 404 на сервере | Адрес картинки должен начинаться с `/assets/…`, сервер запускайте из нужной папки этапа |
