## 2. Текущий контроль: тесты

### 2.1. Спецификация

- 11 тестов по числу тем 0–10.
- В каждом **30** закрытых вопросов, один правильный ответ (A–D).
- Время: **25–30 минут**.
- Вопросы **общие** (HTML, HTTP, SQL…), не про имена слоёв учебного магазина.
- Сдача: номер вопроса и буква **или** попытка в Moodle (GIFT).
- Печать для аудитории: файл **без** секции «Ключ».

Порог и перевод в оценку:

| Балл (из 30) | % | Оценка текущего контроля |
| --- | --- | --- |
| 27–30 | ≥ 90 | 5 (отлично) |
| 24–26 | 80–89 | 4 (хорошо) |
| 20–23 | 67–79 | 3 (зачтено / удовлетворительно) |
| 0–19 | < 67 | 2 (не зачтено) |

Минимум для перехода к следующей теме: **20/30**, если преподаватель не установил иной порог.

Ключи хранятся в конце каждого `tests/NN-*.md` (студентам не выдавать). На этапах 0–1 правильный ответ не всегда «A»; в Moodle правильный ответ всегда первый вариант.

## 3. Текущий контроль: практические срезы

Преподаватель открывает работу студента в браузере **без сборки**. С этапа 5 — только через `http://localhost`, не `file://`.

Оценка среза: **зачтено / не зачтено**. Незачёт блокирует следующую тему.

### Тема 0. Макет

- [ ] Названы блоки главной сверху вниз (не меньше 8).
- [ ] Для блока указаны смысл для пользователя и предполагаемый HTML-тег.
- [ ] Сняты цвета (HEX) и семейства шрифтов.
- [ ] Отмечен повторяющийся компонент и состояния (hover, sale).
- [ ] ДЗ: подписаны ≥5 блоков.

### Тема 1. HTML (`stage-01-html`)

- [ ] Валидатор без ошибок по обязательным полям.
- [ ] Один `h1`; логотип не подменяет иерархию.
- [ ] Картинки с `alt`.
- [ ] У полей форм есть связанный `label`.
- [ ] Страница читается при отключённых стилях.
- [ ] Shop now — ссылка; Submit в форме — `button`.

### Тема 2. CSS (`stage-02-css`)

- [ ] Токены в `:root` (primary, цвет текста, контейнер).
- [ ] Шапка в ряд (flex); каталог сеткой; `gap` из макета.
- [ ] Hover кнопок; есть `:focus-visible`.
- [ ] На широком экране ритм близок к макету (не «примерно фиолетовый»).
- [ ] Нет Bootstrap / инлайн-стилей как системы.

### Тема 3. БЭМ (`stage-03-bem`)

- [ ] Классы вида `блок`, `блок__элемент`, `блок_модификатор`.
- [ ] Карточка переносится в другое место без поломки стилей.
- [ ] Нет цепочек `.header nav ul li a` как основы стиля.
- [ ] Визуал совпадает с этапом 2.

### Тема 4. Модалки (`stage-04-modals`)

- [ ] Account открывает `#modal-auth` по hash без JS.
- [ ] Карточка открывает `#modal-product`.
- [ ] Есть оверлей и крестик с понятным именем / `type="button"`.
- [ ] `role="dialog"`, заголовок связан (`aria-labelledby` или видимый `h2`).

### Тема 5. JavaScript (`stage-05-js`)

- [ ] Открыто через локальный сервер; карточки с JSON.
- [ ] Карточка → модалка → Select без входа → Account.
- [ ] После входа выбор сохраняется (перезагрузка).
- [ ] Esc и клик по оверлею закрывают диалог.
- [ ] Невалидный email не «отправляет» форму.

### Тема 6. Сервер (`stage-06-server`)

- [ ] Поднят один стек; фронт ходит в API.
- [ ] Регистрация / вход; повторный email — 409.
- [ ] Без сессии защищённый метод — 401.
- [ ] Выбор товара после F5 на месте.
- [ ] URL и JSON совпадают с контрактом (не «свой диалект»).

### Тема 7. Адаптив (`stage-07-adaptive`)

- [ ] 1280 / 1024 / 768 / 375 просмотрены.
- [ ] На 768 есть бургер, меню открывается.
- [ ] На 375 нет горизонтального скролла всей страницы.
- [ ] Стили блока лежат в папке блока, `@media` не свалены в конец одного файла.

### Тема 8. ООП (`stage-08-oop`)

- [ ] Поведение как на этапе 5 (сценарии те же).
- [ ] Вход через `App` / `type="module"`.
- [ ] Модалка входа — наследник базовой модалки (или эквивалент «является»).
- [ ] Нет «простыни» глобальных функций как единственной архитектуры.

### Тема 9. БД (`stage-09-database`)

- [ ] `GET /api/products` из SQLite.
- [ ] Регистрация появляется в `users`.
- [ ] Контракт HTTP не разъехался с этапом 6.
- [ ] Пароль в таблице не открытым текстом (хеш).

### Тема 10. Магазин (`stage-10-shop-admin`)

- [ ] Пользователь: в корзину → Checkout → список заказов.
- [ ] Пустая корзина на checkout — ошибка 4xx, не «пустой заказ 200».
- [ ] Админ (`admin@coral.local`) добавляет карточку, она на витрине.
- [ ] Не-админ на админский POST получает 403.
- [ ] Старые заказы не пересчитываются после смены цены карточки.

## 4. Промежуточная аттестация

**Форма:** дифференцированный зачёт.  
**Допуск:** все темы 0–10 имеют зачтённый практический срез; средняя оценка тестов не ниже 3 (допускается один повторённый тест).

Зачёт состоит из двух частей, обе обязательны.

### 4.1. Часть А. Защита проекта (практика)

Студент демонстрирует **свою** папку (не эталон `stage-10` без вклада). Преподаватель гоняет сценарий 10–15 минут.

| Критерий | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Главная по макету (блоки, токены, сетка) | нет | частично | да |
| Семантика и формы | грубые ошибки | мелкие | ок |
| Модалки и JS (Esc, валидация, каталог) | не работает | частично | сценарии guide 5 |
| Сервер + БД (вход, данные после F5) | нет | вход есть, данные плавают | контракт соблюдён |
| Адаптив 768 / 375 | сломан | терпимо | бургер, нет гориз. скролла |
| Корзина, заказ, права админа | нет | один сценарий | оба сценария + 403 |

Сумма части А: **0–12 баллов**.

Минимум допуска к части Б: **6 баллов**. Иначе «неудовлетворительно» без собеседования.

### 4.2. Часть Б. Собеседование (теория)

Студент тянет билет: **два** вопроса из разных тем (таблица билетов ниже). Ответ устный, 5–7 минут, с опорой на свой код по желанию преподавателя.

Оценка ответа по каждому вопросу: 0 (неверно), 1 (с наводкой), 2 (верно, своими словами). Сумма части Б: **0–4 балла**.

### 4.3. Итоговая оценка зачёта

Сумма А+Б: **0–16**.

| Сумма | Оценка |
| --- | --- |
| 14–16 | отлично |
| 11–13 | хорошо |
| 8–10 | удовлетворительно |
| 0–7 | неудовлетворительно |

При оценке «отлично» тесты текущего контроля в среднем не ниже 4, иначе оценка снижается на один балл (но не ниже «хорошо», если сумма 14–16 и среднее тестов = 3 — преподаватель фиксирует в ведомости «хорошо»).

| Билет | Вопрос 1 | Вопрос 2 |
| --- | --- | --- |
| 1 | Зачем в макете сетка и max-width? | Чем `<article>` отличается от `<div>`? |

### 4.5. Типовые формулировки ответов (ориентир преподавателю)

Полные разборы — в лекциях `docs/course/lectures/*/lecture.md`. Кратко:

- Сетка — единая система выравнивания; max-width не даёт строке расползтись на ультрашироком.
- Токен — именованное значение, одно изменение правит кнопки и бейджи.
- `article` — самостоятельный фрагмент смысла (карточка товара).
- 401 — «кто вы?»; 403 — «знаем кто, нельзя».
- Цену копируют, потому что витрина позже изменится, а чек — юридический снимок.
- Склейка SQL с вводом — инъекция; плейсхолдер `?` / параметры ORM.
