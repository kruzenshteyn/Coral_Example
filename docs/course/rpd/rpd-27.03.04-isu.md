## 1. Цели и задачи освоения дисциплины

### 1.1. Цель

Сформировать способность **ставить задачу, проектировать и реализовывать информационную систему управления (ИСУ) объектом цифрового контура**: сбор требований к интерфейсу, клиент-серверное взаимодействие, хранение состояния, контуры учёта (каталог → выбор → заказ) и администрирование справочника.

Учебный объект управления — коммерческий контур интернет-магазина **CORAL** (номенклатура, пользователи, заказы, роли). Это не «сайт в конструкторе», а нарастающая ИСУ: требования (макет) → представление → логика управления на клиенте → API как канал управления → хранилище → контуры заказа и админки.

### 1.2. Задачи

1. Формализовать требования к ИСУ по макету интерфейса (блоки, токены, состояния, роли пользователей).
2. Реализовать человеко-машинный интерфейс управления (HTML/CSS, независимые блоки, диалоги).
3. Реализовать контур обратной связи на клиенте (события, валидация, загрузка состояния).
4. Спроектировать канал управления — HTTP-API с сессией и кодами ответа (единый контракт, три стека на выбор).
5. Перенести состояние объекта в реляционное хранилище без ломки интерфейса управления.
6. Замкнуть контуры: корзина и заказ (фиксация решения), админка справочника, разграничение прав.

### 1.3. Место в ОПОП

Дисциплина вариативной части. Связана с информатикой, программированием, базами данных и дисциплинами профиля «информатика в технических системах». Готовит к практикам и ВКР, где нужна ИСУ с веб-интерфейсом оператора / администратора.

### 2.2. Знать / уметь / владеть

**Знает:** состав ИСУ (интерфейс, логика, канал, хранилище); формализацию требований по макету; HTML/CSS/JS как средства HMI; HTTP как протокол управления; сессию и роли; реляционное хранение состояния; фиксацию управленческого решения (заказ как снимок).

**Умеет:** поставить задачу управления витриной; реализовать контуры входа, выбора, заказа; разграничить права; перенести состояние в БД без смены контракта.

**Владеет:** навыком реализации учебной ИСУ с веб-интерфейсом на проекте CORAL.

## 5. Содержание дисциплины

Студент работает в своей папке. Эталоны — `stage-01-html` … `stage-10-shop-admin`.

### Тема 0. Требования к ИСУ

Макет как спецификация человеко-машинного интерфейса: сетка, токены, состояния, роли (гость / пользователь / админ — задел). Практика: карта блоков Coral. Тест `tests/00-figma.md`.

### Тема 1. Представление: HTML

Документ как модель экрана оператора. Семантика, формы ввода управляющих воздействий (поиск, рассылка, вход на `login.html`). Эталон `stage-01-html/`. Тест `tests/01-html.md`.

### Тема 2. CSS

Отображение по ТЗ, токены, Flex/Grid. Адаптив — тема 7. Эталон `stage-02-css/`. Тест `tests/02-css.md`.

### Тема 3. БЭМ

Декомпозиция интерфейса на независимые блоки управления. Эталон `stage-03-bem/`. Тест `tests/03-bem.md`.

### Тема 4. Диалоги

Модальный контур ввода (вход, карточка) без смены «режима объекта». `:target`. Эталон `stage-04-modals/`. Тест `tests/04-modals.md`.

### Тема 5. Логика на клиенте

Обратная связь: события, валидация, загрузка каталога, локальное состояние. Эталон `stage-05-js/`. Тест `tests/05-js.md`.

### Тема 6. Канал управления

HTTP как протокол воздействий и измерений (GET — наблюдение, POST — команда). Сессия, коды 401/403/409. Три реализации, один контракт. Эталон `stage-06-server/`. Тест `tests/06-server.md`.

### Тема 7. Адаптив HMI

Управление с разных ширин экрана, бургер как свёртка панели команд. Эталон `stage-07-adaptive/`. Тест `tests/07-adaptive.md`.

### Тема 8. Структура программного обеспечения

Классы как модули контура (`Catalog`, `Modal`, `App`). Эталон `stage-08-oop/`. Тест `tests/08-oop.md`.

### Тема 9. Состояние объекта

Реляционное хранение: PK/FK, транзакция, защита запросов. API не меняется. Эталон `stage-09-database/`. Тест `tests/09-database.md`.

### Тема 10. Контуры учёта

Корзина — черновик решения; заказ — фиксация (снимок цены); админка — управление справочником; 403 — отказ в праве на воздействие. Эталон `stage-10-shop-admin/`. Тест `tests/10-shop-admin.md`.

### Тема 11. Зачёт

Защита ИСУ: сценарии гость / пользователь / админ, ответы по контуру управления.
