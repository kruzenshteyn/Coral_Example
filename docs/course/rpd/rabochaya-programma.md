## 1. Пояснительная записка

### 1.1. Назначение

Рабочая программа задаёт цели, результаты, объём, содержание и условия реализации учебной дисциплины (модуля) по сквозному учебному проекту **CORAL**: интернет-магазин одежды и аксессуаров по макету Figma.

Студенты не собирают сайт в конструкторе. Один проект нарастает слоями: макет → HTML → CSS → БЭМ → модальные окна → JavaScript → HTTP-API (PHP / Django / Node.js) → адаптив → ООП → SQLite → корзина и админка.

Материалы дисциплины:

- макет `Coral.fig` и токены `design/tokens.md`;
- эталоны `stage-01-html` … `stage-10-shop-admin`;
- лекции `docs/course/lectures/`;
- инструкции `docs/course/guides/`;
- тесты текущего контроля `docs/course/tests/` (30 вопросов на тему).

### 1.2. Цель

Сформировать умение **разработать и сдать работающий продающий сайт по макету**: семантическая вёрстка, стили и адаптив, клиентское поведение, серверный API с сессией, хранение данных и сценарии покупки / администрирования карточек.

### 1.3. Задачи

1. Читать макет как техническое задание (сетка, токены, состояния UI).
2. Верстать документ HTML без опоры на «картинку».
3. Переносить токены макета в CSS (каскад, сетка, типографика).
4. Рефакторить имена по БЭМ и собирать интерфейс из независимых блоков.
5. Верстать и подключать модальные диалоги, затем поведение на JavaScript.
6. Реализовать один HTTP-контракт на выбранном стеке (PHP, Django или Node.js).
7. Обеспечить адаптив и файловую структуру стилей.
8. Рефакторить клиентский код на классы и модули.
9. Заменить файловое хранилище на SQLite без ломки API.
10. Реализовать корзину, заказ, разграничение прав и форму новой карточки.

### 1.4. Место в образовательной программе

Дисциплина (междисциплинарный курс / ДПП) опирается на базовые навыки работы с файлами, браузером и редактором кода. Параллельно или ранее желательны основы информатики.

Рекомендуемая привязка к ФГОС СПО 09.02.07: профессиональные модули, связанные с дизайном и разработкой веб-приложений. Конкретные индексы ПК образовательная организация вписывает в свою ОПОП.

### 1.5. Планируемые результаты

**Иметь практический опыт:**

- съёма блоков и токенов из макета Figma и фиксации их как ТЗ;
- вёрстки многоблочной главной интернет-магазина;
- подключения клиентской логики (диалоги, валидация, загрузка каталога);
- запуска учебного API и проверки запросов;
- оформления заказа и добавления карточки товара от имени администратора.

**Уметь:**

- выбирать HTML-тег по смыслу блока, связывать `label` с полем, задавать `alt`;
- описывать раскладку Flex/Grid, токены в `:root`, состояния `:hover` / `:focus-visible`;
- именовать блоки, элементы и модификаторы по БЭМ;
- открывать диалог (сначала `:target`, затем скриптом) с оверлеем и клавишей Escape;
- загружать JSON/`fetch`, хранить выбор в `localStorage`, затем в сессии сервера;
- различать коды HTTP 200 / 400 / 401 / 403 / 404 / 409 / 500;
- задавать брейкпоинты и медиазапросы в файле блока;
- выделять классы с одной ответственностью, наследовать модалку, собирать фасад приложения;
- писать параметризованный SQL, объяснять PRIMARY KEY и FOREIGN KEY;
- копировать цену в позицию заказа, проверять роль на сервере, экранировать вывод.

**Знать:**

- устройство макета (сетка, 8px-ритм, компоненты, прототип);
- каркас HTML-документа, семантику, формы, валидность;
- каскад, специфичность, блочную модель, единицы CSS;
- правила БЭМ и отличие от «ложного БЭМ»;
- требования доступности к диалогу;
- основы языка JavaScript в браузере;
- методы и коды HTTP, cookie-сессию, CORS/CSRF на уровне учебной модели;
- стратегии mobile-first и desktop-first;
- инкапсуляцию, наследование, композицию, модули ES;
- основы реляционной модели и SQLite;
- разницу аутентификации и авторизации, XSS, валидацию на сервере.

## 4. Содержание дисциплины

Студент выполняет работу в **своей** папке (например `site/`). Каталоги `stage-N` — эталон преподавателя, не место правок.

На каждом этапе цикл: лекция → инструкция `guides/` → практика по эталону → «Проверка» → тест 30 вопросов.

### Тема 0. Макет как ТЗ

**Лекция.** Макет — спецификация, не скриншот. Сетка и 12 колонок, max-width, шаг 8px, токены цвета и радиуса, line-height, компонент и Auto Layout, hover/disabled, вектор и @2x, контраст, breakpoint, pixel-perfect.

**Практика.** Открыть `Coral.fig`. Выписать блоки сверху вниз, 5–8 цветов, 2–3 семейства шрифтов, повторяющийся компонент, наличие mobile-фрейма. ДЗ: подписать ≥5 блоков (тег, зачем пользователю, состав).

**СРС.** Дочитать карту блоков `docs/course/00-figma.md`, сверить с `design/tokens.md`.

**Срез.** Таблица блоков + токены. Тест `tests/00-figma.md`.

**Эталон.** Карта макета; к вёрстке не переходят без таблицы.

### Тема 1. HTML

**Лекция.** Doctype, `lang`, charset, viewport, семантика (`header`, `nav`, `main`, `article`, `footer`), ссылка vs кнопка, `alt`, `label`/`for`, иерархия заголовков, формы, `hidden`, валидатор.

**Практика.** Собрать `index.html` (и запасные `login.html`, `product.html`) так, чтобы страница читалась без CSS. Карточка — `article`. Рассылка и поиск — формы с видимым `label`. Account и товар — отдельные страницы; модалки — тема 4.

**Приёмка.** Валидатор; один `h1`; `alt`; связанные подписи; страница понятна при отключённых стилях.

**Срез.** Тест `tests/01-html.md`. Эталон: `stage-01-html/`.

### Тема 2. CSS

**Лекция.** Каскад и специфичность, `border-box`, Flex и Grid, `absolute`, `em`/`rem`, кастомные свойства, `:hover` / `:focus-visible`, `object-fit`, `@media` как понятие.

**Практика.** Токены Coral в `:root` (primary `#9E5CF2`, текст `#1E2832`, контейнер 1320px). Шапка — flex, каталог — grid 4 колонки, `gap` 24px. Классы пока простые (`header`, `hero`, `btn`). Без БЭМ, без Bootstrap.

**Срез.** Визуал близок к макету на широком экране. Тест `tests/02-css.md`. Эталон: `stage-02-css/`.

### Тема 3. БЭМ

**Лекция.** Блок, элемент, модификатор; независимость; микс; запрет `block__el__sub`; файл на блок; «ложный БЭМ».

**Практика.** Рефакторинг этапа 2: `header__top`, `product-card__media`, `product-card__badge_type_sale`, `product-card_selected`. Карточка не зависит от секции (её можно перенести).

**Срез.** Тест `tests/03-bem.md`. Эталон: `stage-03-bem/`.

### Тема 4. Модальные окна

**Лекция.** Оверлей, `role="dialog"`, `aria-modal`, `:target` без JS, `type="button"` у крестика, z-index, отличие от `alert()`. Фокус и Escape — задел темы 5.

**Практика.** `#modal-auth`, `#modal-product`. Account → `#modal-auth`, карточка → `#modal-product`, закрытие → `#`. Стили `modal.css`.

**Срез.** Диалог открывается по hash без скрипта. Тест `tests/04-modals.md`. Эталон: `stage-04-modals/`.

### Тема 5. JavaScript в браузере

**Лекция.** `const`/`let`, DOM, делегирование, `preventDefault`, `fetch` и `response.ok`, `localStorage`, `classList`, debounce, `file://` vs локальный сервер.

**Практика.** Каталог из `data/products.json`. Класс `modal_open`, Escape и оверлей. Выбор товара без входа → модалка Account; после входа — `localStorage` и рамка. Валидация email. Запуск: `python -m http.server 8080`.

**Срез.** Сценарии приёмки guide этапа 5. Тест `tests/05-js.md`. Эталон: `stage-05-js/`.

### Тема 6. HTTP, API и сервер

**Лекция.** GET/POST, коды 200–500, JSON, маршрутизация, сессия и HttpOnly, пароль как хеш, CORS, CSRF, три стека — один контракт.

**Практика.** Контракт `stage-06-server/api-contract.md`. Группа выбирает PHP (:8000), Django (:8001) или Node (:8002). Регистрация, вход, выбор товара переживает перезагрузку. Прогон: `TESTING.md`, `docs/course/api-tests.md`.

**Срез.** curl/Postman по контракту; 401 без сессии; 409 на занятый email. Тест `tests/06-server.md`.

### Тема 7. Адаптив и CSS по блокам

**Лекция.** Viewport, desktop-first (как в Coral), брейкпоинты, fluid, бургер, hit area, `srcset`, медиа в файле блока.

**Практика.** Структура `css/blocks/…`. Брейкпоинты 1100 / 768 / 480. Бургер на 768. Проверка DevTools: 1280, 1024, 768, 375.

**Срез.** Нет горизонтального скролла страницы на 375px; бургер открывается. Тест `tests/07-adaptive.md`. Эталон: `stage-07-adaptive/`.

### Тема 8. ООП в JavaScript

**Лекция.** Класс и экземпляр, инкапсуляция, `extends` / `super`, композиция vs наследование, `this`, модули, фасад, SRP.

**Практика.** Поведение как на этапах 5 и 7. Классы: `Product`, `Catalog`, `Modal` → `AuthModal` / `ProductModal`, `App`. Вход `js/App.js`, `type="module"`, локальный сервер.

**Срез.** Те же пользовательские сценарии. Тест `tests/08-oop.md`. Эталон: `stage-08-oop/`.

### Тема 9. База данных SQLite

**Лекция.** Таблица, PK/FK, UNIQUE, NULL, CRUD SQL, JOIN, транзакция, инъекция и плейсхолдеры, миграция, seed.

**Практика.** `data/schema.sql`: `users`, `products`, `selected_products`. HTTP-контракт этапа 6 не меняется. Сид `admin@coral.local`. Регистрация пишет строку в `users`.

**Срез.** `GET /api/products` отдаёт каталог из `.db`. Тест `tests/09-database.md`. Эталон: `stage-09-database/`.

### Тема 10. Корзина, заказ, админка

**Лекция.** Аутентификация vs авторизация, корзина vs заказ, снимок цены, checkout, 403, XSS, CSRF, валидация на сервере.

**Практика.** `/api/cart`, `/api/checkout`, `/api/purchases`, `/api/admin/products`. Страницы `cart.html`, `purchases.html`, `admin.html`. Сценарий: покупатель → корзина → заказ; админ добавляет карточку.

**Срез.** Пустая корзина на checkout — 4xx; чужая корзина недоступна; админ без роли — 403. Тест `tests/10-shop-admin.md`. Эталон: `stage-10-shop-admin/`.

### Тема 11. Итоговое занятие

Разбор частых ошибок (file://, расхождение стеков, «div-суп», потерянные состояния). Защита проекта по чек-листу ФОС. Дифференцированный зачёт.

## 7. Условия реализации

### 7.1. Материально-технические

- компьютерный класс: браузер (Chrome / Edge / Firefox), редактор кода (VS Code или аналог);
- локальный запуск: Python 3 (модуль `http.server`); по выбору группы — PHP **или** Node.js **или** Python + Django;
- доступ к файлам курса (репозиторий) и макету `Coral.fig` (Figma или копия файла).

Сборщики, Bootstrap и React на дисциплине **не используются**.

### 7.2. Информационные

**Основные:**

1. Материалы курса CORAL: `docs/course/` (лекции, guides, тесты), эталоны `stage-*`.
2. MDN Web Docs. URL: https://developer.mozilla.org/ru/
3. Спецификации HTML и CSS (WHATWG, W3C) — по ссылкам из guides.

**Дополнительные:**

1. Справка Figma: Components, Auto layout. https://help.figma.com/
2. Документация выбранного стека: PHP, Django, Node.js.
3. SQLite. https://www.sqlite.org/docs.html

**Электронная среда.** Тесты можно импортировать в Moodle (GIFT): `docs/course/tests/moodle/`.

### 7.3. Кадровые

Преподаватель с опытом вёрстки и хотя бы одного из стеков PHP / Django / Node.js. На теме 6 группа может разделиться по стекам при общем контракте API.

## 8. Методические указания

Порядок работы студента — `docs/course/metodika-po-shagam.md`:

1. Прочитать guide целиком, включая «Почему так».
2. Не копировать эталон слепо; писать в своей папке `site/`.
3. Сверяться с `stage-N` по блокам, не одним взглядом в конце.
4. Пройти «Проверку» guide до теста.
5. Тест — про понимание; при ошибке вернуться к лекции и «Почему так».

Запрещено на дисциплине: править эталон вместо своей папки; подключать UI-фреймворки; расходиться по URL/JSON между серверными вариантами.
