# Этап 8. Рефакторинг JS на ООП

Папка: `stage-08-oop/`.

Поведение сайта то же, что на этапах 5 и 7. Меняется устройство кода: функции и глобальный `PRODUCTS` заменены классами и ES-модулями.

Нужен локальный сервер: и `fetch`, и `type="module"` не работают с `file://`.

```
cd stage-08-oop
python -m http.server 8080
```

## Что вынесли в классы

| Класс | Роль | ООП-приём |
| --- | --- | --- |
| `Product` | данные одной карточки, цена, бейдж | инкапсуляция |
| `ProductCard` | DOM карточки | один объект — один кусок UI |
| `Catalog` | загрузка JSON, поиск, отрисовка сеток | композиция карточек |
| `StorageBox` | чтение/запись `localStorage` | переиспользование |
| `UserSession` | вход / имя в шапке | композиция `StorageBox` |
| `Selection` | выбранные товары, рамка, бейдж корзины | композиция `StorageBox` |
| `Modal` | открыть / закрыть / Esc-фокус | базовый класс |
| `AuthModal` | вкладки, валидация, логин | наследование от `Modal` |
| `ProductModal` | подстановка товара, Select | наследование от `Modal` |
| `FormValidator` | email и ошибки полей | статические методы |
| `BurgerMenu` | меню на 768px | маленький UI-объект |
| `CategoryTabs` | фильтр Best sellers | маленький UI-объект |
| `App` | собирает всё вместе, `start()` | фасад |

Точка входа — `js/App.js`:

```html
<script type="module" src="js/App.js"></script>
```

## Схема на доске

```
App
 ├─ Catalog ── Product ── ProductCard
 ├─ UserSession ── StorageBox
 ├─ Selection ── StorageBox
 ├─ AuthModal ── Modal
 └─ ProductModal ── Modal
```

Наследование только там, где «является»: модалка входа — это модалка. Каталог не наследуют от списка — он **содержит** карточки.

## Сравнение с этапом 5

- Было: `let PRODUCTS = []` и функции `loadProducts`, `openModal` в одном IIFE.
- Стало: состояние живёт в экземплярах, модалки не знают про `localStorage`, `App` только связывает события.

## Приёмка

Те же сценарии, что на этапе 5: карточка → модалка → Select без входа → Account; после входа выбор сохраняется; Esc закрывает; JSON рисует сетку.
