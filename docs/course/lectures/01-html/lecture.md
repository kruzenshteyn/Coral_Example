# Вводная лекция. HTML как смысл страницы

Этап 1 курса. Тема теста: [HTML](../../tests/01-html.md) — общие правила разметки, **не** про имена классов Coral.

Живые примеры к этой лекции: [examples.html](examples.html) (открыть в браузере).

Эталон этапа: `stage-01-html/`.  
Как собрать страницу руками: [../../guides/01-html.md](../../guides/01-html.md).

---

## Зачем эта лекция

HTML описывает **документ**, не картинку. Браузер, скринридер и поисковик читают теги и атрибуты. CSS потом красит то, что уже имеет смысл.

На этапе 1 страница должна читаться **без стилей**: заголовки, списки, подписи полей, картинки с текстом вместо файла. Если без CSS остаётся каша из `div` — разметка ещё не готова.

На тесте правильный ответ почти всегда про **смысл тега или атрибута**, а не про SQL, DNS, Docker и цвет кнопок.

## 1. Каркас документа

Каждая страница начинается одинаково: режим стандарта, язык, кодировка, ширина экрана, заголовок вкладки. Стили подключают в `<head>`, не внутри абзаца.

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>CORAL — Collections</title>
    <link rel="stylesheet" href="css/style.css" />
  </head>
  <body>…</body>
</html>
```

В Coral контент макета на английском — поэтому `lang="en"`. Язык ставят по тексту страницы, не «всегда ru».

### `<!DOCTYPE html>`

Сообщает браузеру **режим стандарта HTML5**. Без него старые браузеры могут включить quirks mode: бокс-модель и отступы поедут. Doctype не подключает CSS, не создаёт БД и не включает JS.

### `lang` у `<html>`

Влияет на **язык для скринридеров и перевода** (произношение, автоперевод, словари). Не на цвет фона и не на PHP.

### `charset`

Чтобы **корректно читать Unicode** — кириллица, ё, тире, символы валют. Без UTF-8 вместо «коллекции» будет «ÐºÐ¾Ð»…». Порт, Grid и cookie тут ни при чём.

Ставят первым в `<head>`, до текста на странице.

### Viewport meta

Нужен для **корректной ширины на мобильных**. Без него телефон рисует страницу как ~980px и уменьшает целиком: буквы мелкие, кнопка «Shop now» не нажимается пальцем.

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

Это не sitemap, не SMTP и не Git. Viewport нужен уже на этапе 1, даже если CSS ещё нет.

### `<link rel="stylesheet">`

Файл стилей обычно ставят **в `<head>`**. Не внутрь `<p>`, не вместо doctype.

На этапе 1 в эталоне CSS ещё нет — и это нормально. Когда файл появится (этап 2), место ему в `head`.

**На тесте:** doctype, lang, charset, viewport, где живёт `link rel="stylesheet"`.

## 2. Семантика: не всё `div`

Тег несёт роль. `div` — нейтральная коробка для CSS. Если у блока есть смысл «шапка / товар / меню» — берут именованный тег.

```text
body
├── header          шапка: поиск, лого, Account
│   └── nav         меню каталога
├── main            одно основное содержимое
│   ├── section     герой, категории, рассылка…
│   └── article     карточка товара
└── footer          подвал страницы
```

### `<header>`

Это **вводный блок страницы или секции**, не «только шапка сайта и больше ничего». У карточки или статьи тоже может быть свой `<header>` (фото + название). Это не HTTP-заголовок ответа.

**Пример из Coral.** Верх страницы — `<header class="header">`: поиск, логотип, Account. Это header страницы. Не путать с `<head>` документа.

### `<main>`

Обычно **один на страницу**: основное содержимое, без повторяющихся шапки и подвала. Не десять, не замена `<html>`, не только в письмах.

Скринридер умеет команду «перейти к main» — если mains несколько, ориентир ломается.

### `<footer>`

Может быть **у страницы и у article**. Подвал карточки (цена, ссылка) — нормально. Не «один на весь интернет» и не CSS-свойство.

**Пример.** В Coral `<footer class="footer">` — колонки Catalog / About / Customer services и копирайт. Если позже у карточки появится свой низ — это второй footer, уже внутри article.

### `<nav>` + список

Навигационные ссылки логично класть в **`<nav>` и список** (`ul`/`ol`). Не в таблицу, не в `<script>`.

```html
<nav class="menu" aria-label="Catalog">
  <ul>
    <li><a href="#products">Clothing &amp; Shoes</a></li>
  </ul>
</nav>
```

`aria-label` отличает меню каталога от меню в подвале — на странице Coral несколько `<nav>`.

### `<section>`

Когда нужен **тематический блок с заголовком**: герой, категории, рассылка. Не для «просто отступа» (это CSS) и не для HTTP POST.

Секция без заголовка — плохой сигнал: зачем тогда не `div`? В Coral у секций есть `h1`/`h2` или хотя бы `aria-label`.

### `<article>` vs `<div>`

Article — **самостоятельный фрагмент смысла**: его можно вынуть из страницы, и он всё ещё понятен (фото, название, цена). Div ничего не значит. Div в HTML5 не запрещён, article стилизовать можно.

```html
<article class="product-card">
  <a href="product.html">
    <img src="images/category-pants.jpg" width="400" height="500"
         alt="Adicolor Classics Joggers" />
    <h3>Adicolor Classics Joggers</h3>
  </a>
  <p>Dress</p>
  <p><data value="63.85">$63.85</data></p>
</article>
```

Одна карточка = один article. Восемь карточек — не восемь уникальных схем, один шаблон.

**На тесте:** header, article, nav, section, main, footer.

## 3. Ссылка, кнопка, картинка

Одинаковый вид в макете не значит одинаковый тег. Переход по адресу — `<a>`. Действие на странице или отправка — `<button>`. Картинка — пустой элемент с `alt`.

### Ссылка на другую страницу

Размечают **`<a href="...">`**. Не `<link>` в body как текст (`link` в head — для стилей и иконок). У `<button>` нет `href`. У `<nav>` нет `src`.

| В Coral | Смысл | Тег |
| --- | --- | --- |
| Shop now → `#products` | переход к каталогу | `<a href="#products">` |
| Account → `login.html` | другая страница | `<a href="login.html">` |
| Submit у рассылки | отправка формы | `<button type="submit">` |

### Отправка формы

Обычно запускает **`<button type="submit">` или `<input type="submit">`**. Не `<a type="submit">` и не картинка.

### `<button>` без `type`

Внутри формы часто ведёт себя **как submit**. Это ловушка: кнопка «Закрыть» без `type="button"` отправит форму входа.

```html
<button type="submit">Sign in</button>
<button type="button">Close</button>
```

Не «всегда reset» и не ссылка.

### `alt` у `<img>`

**Запасной текст**, если картинки нет, и описание для скринридера. Не URL (это `src`), не ширина в см, не цвет рамки.

Пишите, *что на фото*, не «image1». Декоративную иконку рядом с видимой подписью можно `alt=""` — но товар без описания так прятать нельзя.

```html
<img src="images/hero-left.jpg" width="640" height="800"
     alt="Woman in a brown wrap dress walking in the city" />
```

`width` и `height` в HTML — чтобы страница не прыгала, пока файл качается. Это не замена CSS.

### Void / empty element

Пустой элемент вроде `<img>`, `<meta>`, `<br>`, `<input>` называют **void / empty**: у него нет закрывающего тега и содержимого. Не live node и не PRIMARY KEY.

Пишут `<img src="…" alt="…">`, не `<img></img>`.

**На тесте:** `a href`, submit, button без type, alt, void-элемент.

## 4. Заголовки, важность, `id`

### Иерархия заголовков

С точки зрения доступности иерархия уровней должна быть **логичной, обычно один главный `h1`**. Не «сколько угодно h1 без порядка» и не «только h6».

В Coral: `h1` — «Collections» в герое. Логотип в шапке — ссылка в `<p class="logo">`, не второй h1. Дальше `h2` секций, `h3` в карточке.

```text
h1 Collections
  h2 Explore new and popular styles
  h2 Products
    h3 Adicolor Classics Joggers
    h3 Nike Sportswear Futura Luxe
  h2 Or subscribe to the newsletter
```

Не прыгать с `h1` сразу на `h4`. Уровень — про структуру, не про кегль (кегль задаст CSS).

### `<strong>` и `<b>`

**strong несёт важность**, `b` — визуальное выделение без обязательного смысла. Это не одно и то же по спецификации. `b` не «семантически сильнее».

| Нужно | Тег |
| --- | --- |
| Цена по акции важна | `<strong>70%</strong>` |
| Название бренда жирным «для вида» | `<b>Zara</b>` |
| Просто жирный абзац | лучше CSS `font-weight` |

Скринридер может усилить голос на `strong`. На `b` — не обязан.

### `id`

Цель — **уникальный якорь и связь на странице**: `label for`, `href="#products"`, `aria-labelledby`. Нельзя повторять один id на каждом div. Class id не заменяет: class — для групп, id — один в документе. Это не SQL PRIMARY KEY браузера.

```html
<h2 id="products-title">Products</h2>
<section id="products" aria-labelledby="products-title">…</section>
<a href="#products">Shop now</a>
```

**На тесте:** иерархия заголовков, strong vs b, зачем id.

## 5. Формы: подпись, типы, отправка

Форма — не набор полей «как в макете», а контракт: что спрашиваем, куда шлём, что обязательно.

```html
<form action="#" method="post">
  <label for="newsletter-email">Email address</label>
  <input
    id="newsletter-email"
    type="email"
    name="email"
    placeholder="Email address..."
    autocomplete="email"
    required
  />
  <button type="submit">Submit</button>
</form>
```

### `for` у label = `id` поля

Чтобы **клик по подписи фокусировал поле**. Это не Grid и не SQL JOIN. Совпадение `for`/`id` как раз обязательно для этой связи (либо поле вкладывают внутрь label).

Placeholder **не заменяет** подпись: он исчезает, когда человек печатает, и скринридер его может пропустить.

### Что озвучит скринридер

Подпись поля — если есть **связанный label (или aria-label)**. Одного placeholder, `name` или CSS `content` недостаточно.

Проверка этапа 1: отключите CSS — подпись «Email address» всё ещё видна рядом с полем.

### Поле пароля

`type="password"` — звёздочки вместо символов, другое поведение автозаполнения. Не `type="hidden"` (это совсем невидимое поле), не обязательный `text`, отдельного тега `<password>` нет.

```html
<label for="auth-password">Password</label>
<input id="auth-password" type="password"
       name="password" autocomplete="current-password" required />
```

Регистрация: `autocomplete="new-password"`. Вход: `current-password`.

### `required`

Браузер **может не дать отправить пустое поле**. Это не шифрование, не SQLite и не «выключить CSS». Проверка на клиенте — удобство; настоящую проверку всё равно делает сервер (этап 6).

### `autocomplete="email"`

Помогает **браузеру подставить сохранённый email**. Не валидирует DNS и не заменяет HTTPS.

### `action` у формы

**URL, куда уйдут данные.** На этапе 1 часто `action="#"` — никуда не ходим, учим разметку. Позже сюда встанет адрес API. Это не цвет кнопки и не имя cookie.

`method="get"` — параметры в URL (поиск). `method="post"` — тело запроса (вход, рассылка).

### `disabled` у input

Поле **не редактируется и обычно не уходит в submit**. Его не удаляют из HTML-файла и не превращают в `type="hidden"`.

Пример: кнопка «Оформить заказ» disabled, пока корзина пуста. Значение disabled-поля сервер не получит — если его всё же надо послать, берут `readonly` или hidden-дубль.

**На тесте:** label, password, required, autocomplete, action, disabled, что слышит скринридер.

## 6. Скрытие, таблицы, вложенность, валидатор

### `hidden`

Скрыть блок **от всех, включая скринридер**. Элемента нет в представлении, пока атрибут не снимут (классом на этапе 4, скриптом на этапе 5).

Не путать:

| Приём | Кто не видит |
| --- | --- |
| `hidden` | все: экран, SR, поиск по странице |
| `alt=""` | только описание картинки |
| CSS `display: none` | похоже на hidden, но это стиль |
| визуально спрятать, оставить в a11y-дереве | `visually-hidden` (для подписи иконки) |

В Coral модалки входа и карточки лежат внизу `index.html` с `hidden` — это заготовки, не картинки диалога.

### Таблица данных

Размечают **`<table>`, `<th>`, `<td>`**. Не div с пробелами и не список с запятыми. JSON-LD — про микроразметку для поисковика, не замена таблицы.

Таблица — когда есть **строки и столбцы** (состав заказа, сравнение размеров). Карточки каталога — не таблица, это список article.

```html
<table>
  <thead>
    <tr><th>Товар</th><th>Цена</th></tr>
  </thead>
  <tbody>
    <tr><td>Adicolor Classics Joggers</td><td>$63.85</td></tr>
  </tbody>
</table>
```

### Вложенность `<p>` в `<p>`

**Невалидна:** браузер закроет первый `p`, второй станет соседом. Не создаёт iframe и не включает JS.

```html
<!-- написали -->
<p>Текст <p>внутри</p> дальше</p>

<!-- браузер поймёт -->
<p>Текст </p>
<p>внутри</p>
дальше
<p></p>
```

Внутри абзаца — `span`, `a`, `strong`, не второй `p` и не `div`.

### Валидатор HTML

Проверяет **соответствие разметки правилам языка**: незакрытые теги, запрещённая вложенность, дубли id, пустой alt, label без поля. Не цвет кнопок, не скорость SQL, не наличие Docker.

Прогон: [validator.w3.org](https://validator.w3.org/). На этапе 1 это приёмка, не формальность: ошибка вложенности всплывёт странным CSS на этапе 2.

**На тесте:** hidden, table, вложенные p, валидатор.

## Как отвечать на тесте

1. Отбросьте SQL, DNS, Docker, SMTP, GPU — ловушки с других этапов.
2. Ищите **роль в документе**: переход vs отправка, смысл vs вид, один main, связанный label.
3. Если вопрос про атрибут (`alt`, `for`, `hidden`, `required`) — что он меняет для человека и браузера, не «как покрасить».

После лекции: сверстать каркас Coral без CSS ([ДЗ этапа 1](../../01-html.md)), прогнать валидатор, отключить стили в DevTools, затем тест.
