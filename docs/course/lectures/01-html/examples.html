Вопросы 1, 2, 14, 15, 28

Каркас документа

Doctype включает стандарт HTML5. lang — для скринридера и перевода. Charset — Unicode. Viewport — ширина телефона. Стили — в head. 

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>CORAL — Collections</title>
    <link rel="stylesheet" href="css/style.css" />
  </head>
  <body>…</body>
</html>

В Coral текст макета английский — lang="en", не «всегда ru».

Ссылка, кнопка, alt, void, type у button

Переход — <a href>. Отправка — <button type="submit">. Кнопка без type внутри формы часто сама отправляет. img — void-элемент с alt.

Вопросы 7, 12, 13, 21, 24, 26, 27

Формы: label, пароль, required, action, disabled

Клик по подписи фокусирует поле. Скринридер читает label, не placeholder. action — URL отправки. Disabled не редактируется и обычно не уходит на сервер.

Кликните «Email address»

for совпадает с id. Пустое поле + required — браузер не отправит. Password скрывает символы.

Только placeholder — плохо для SR

Подписи нет: placeholder исчезнет при вводе. Скринридер может сказать «пустое поле». Нужен label или aria-label.

disabled не в submit

Нажмите «Отправить»: в адресе будет note=ok, поля promo нет — disabled не уходит в submit.

Вопросы 18, 20, 25, 30

hidden, таблица, вложенные p, валидатор

hidden прячет блок от всех, включая скринридер. Таблицу данных размечают table/th/td. p внутри p браузер сам разорвёт.

Атрибут hidden

Этот абзац без hidden — его видно.

Этот абзац с hidden: на экране его нет, скринридер тоже молчит.

<p hidden>…</p>

Скрытый блок остаётся в HTML, его не рисуют. Не путать с alt="" у картинки.

<p> внутри <p> — невалидно

<p>Текст <p>внутри</p> дальше</p>

браузер сделает:
<p>Текст </p>
<p>внутри</p>
дальше
<p></p>

Внутри абзаца — span, a, strong. Не второй p.

Что смотрит валидатор

  • один doctype, charset, уникальные id
  • запрещённая вложенность (p в p)
  • img без alt, label без поля
  • не закрытые не-void теги
