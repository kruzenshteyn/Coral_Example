## Зачем эта лекция

Попап — не картинка поверх страницы и не `alert()`. Это **отдельный слой UI**: оверлей, фокус, смысл «пока открыто — страница недоступна». На этапе 4 вёрстка и `:target`. Класс `modal_open` уже есть в CSS — этап 5 только переключит его.

В Coral два окна: `#modal-auth` (вход) и `#modal-product` (карточка). Ссылка Account ведёт на `#modal-auth`. Крестик и оверлей — ссылки на `#`.

На тесте правильный ответ почти всегда про **блокировку страницы, фокус и имя кнопки**, а не про SQL, DNS, Docker и WebSocket.

---

## 1. Суть: слой поверх страницы

Модальное окно обычно **блокирует работу со страницей, пока открыто**. Не новая вкладка, не «только `alert()`», не HTTP 101.

Пользователь не кликает «Shop now» и не скроллит каталог, пока не закроет Account. Это договор UX, не свойство CSS само по себе — его собирают из оверлея, `fixed`, `z-index` и фокуса.

### Оверлей

Нужен, чтобы **затемнить фон и ловить клик «снаружи»**. Не ускоряет CSS, пароли не хранит, `<main>` не заменяет.

```html
<div class="modal" id="modal-auth">
  <a class="modal__overlay" href="#" aria-label="Close"></a>
  <div class="modal__dialog">…</div>
</div>
```

```css
.modal__overlay {
  position: absolute;
  inset: 0;
  background: rgba(30, 40, 50, 0.55); /* --color-black с прозрачностью */
}
```

Клик по затемнению = «закрыть». Сама форма входа клик не получает — панель выше оверлея.

### Почему не `alert()`

`alert()` **плох для UI магазина**: не стилизуется, блокирует поток JS, слабая кастомизация доступности. Спецификация HTML его не запрещает, в Chrome работает, HTTPS не требует.

Нельзя покрасить в primary `#9e5cf2`, нельзя поставить логотип CORAL, нельзя ловушку фокуса. Для удаления товара и входа — свой диалог.

### `position: fixed`

Держит диалог **относительно окна просмотра** (viewport). Не относительно таблицы, из слоя композиции не удаляет, `static` не делает.

```css
.modal {
  position: fixed;
  inset: 0;
  z-index: 40;
  display: flex;
  align-items: center;
  justify-content: center;
}
```

Скролл страницы не уносит окно. `absolute` отсчитывался бы от предка — при `transform` на шапке уехал бы не туда.

### `z-index`

У диалога должен быть **выше основного контента и обычно оверлея**. Не меньше 0 всегда, не равен z-index абзаца, к `fixed` применим.

В Coral шапка `z-index: 20`, модалка `40`. Панель `.modal__dialog { z-index: 1 }` — внутри модалки, над оверлеем. Иначе крестик окажется под затемнением и не кликнется.

**На тесте:** блокирует страницу, оверлей, alert плох, fixed к viewport, z-index выше контента и оверлея.

## 2. Доступность

Визуально «окно поверх» недостаточно. Скринридер и клавиатура должны понять: это диалог, фон неактивен, фокус внутри.

### Роль и имя

Для доступности диалогу часто ставят **`role="dialog"` и `aria-modal="true"`**. Не `role="banner"`, не `rel="modal"`, не `type="dialog"` у html.

`aria-labelledby` указывает **на id заголовка диалога**, не на URL картинки, не cookie, не SQL.

`aria-modal="true"` сообщает, что **контент вне диалога воспринимается как неактивный**. Не про `<model>`, не WebGL, не REST.

```html
<div
  class="modal"
  id="modal-auth"
  role="dialog"
  aria-modal="true"
  aria-labelledby="auth-title"
>
  …
  <h2 class="modal__title" id="auth-title">Account</h2>
</div>
```

Скринридер скажет «Account, диалог», а не «безымянный регион».

### Фокус внутрь

При открытии фокус логично **перенести внутрь** (заголовок, поле или крестик). Не оставлять на футере, tabindex со всего документа навсегда не снимают, `window.close()` не вызывают.

На этапе 5 JS сделает `closeBtn.focus()`. На этапе 4 без JS фокус останется на ссылке Account — это как раз слабость `:target`.

### Focus trap

**Tab циклится внутри диалога.** Не отключает клавиатуру ОС, CSS не блокирует, это не SQL LOCK.

Последний элемент + Tab → первый (крестик или поле Email). Shift+Tab с первого → последний. Иначе Tab уйдёт на «Shop now» под оверлеем.

### `inert` на фоне

Где поддерживается, **делает фон недоступным для взаимодействия**. JPEG не сжимает, CORS не включает, worker не создаёт.

Альтернатива до поддержки `inert` — ловушка фокуса скриптом и `aria-hidden="true"` на `#top` / `<main>`.

### Кнопка закрытия с именем

Должна быть **настоящей кнопкой или ссылкой с понятным именем**. Не только CSS `::after` без текста и a11y-имени, не `<meta>`, не фон оверлея без hit-area.

Почему нельзя закрывать **только иконкой без текста/aria**: **скринридер не поймёт кнопку**. CSS крестик нарисует, браузер кнопку не удалит, Grid не сломается.

```html
<a class="modal__close" href="#" aria-label="Close">&times;</a>
```

`&times;` для глаза, `aria-label="Close"` для имени. В эталоне Coral так у крестика и у оверлея.

### `tabindex="-1"`

Фокус на такой элемент **программно можно, в Tab-цикл не входит**. Не невозможен, не равен `tabindex="0"`, элемент не удаляет.

```html
<h2 id="auth-title" tabindex="-1">Account</h2>
```

JS ставит фокус на заголовок — скринридер читает имя диалога. Дальше Tab идёт к полям, не «застревает» на h2 как на третьей вкладке.

**На тесте:** role/aria-modal, labelledby, фокус внутрь, trap, имя кнопки, inert, aria-modal про фон, tabindex=-1, нельзя только иконка.

## 3. UX закрытия

Закрыть должно быть легко — и нельзя потерять данные или фокус.

### Escape

Клавиша **обычно закрывает диалог**. Не отправляет форму, localStorage не чистит «всегда», язык не меняет.

На этапе 4 без JS Escape не сработает — его навесят на этапе 5. В примерах лекции обработчик уже есть, чтобы показать паттерн.

### Скролл body

При открытом диалоге прокрутку **часто блокируют (`overflow: hidden` на body)**. Не обязана остаться, в CSS возможна, iframe не нужен.

```css
body.modal-open {
  overflow: hidden;
}
```

Иначе пользователь прокрутит каталог под оверлеем и «потеряет» место.

Длинный контент внутри окна — **`overflow: auto` на панели диалога**, не увеличение `html` font-size, текст не запрещают, новая страница не обязательна.

```css
.modal__dialog {
  max-height: calc(100vh - 32px);
  overflow: auto;
}
```

Форма регистрации Coral с четырьмя полями на узком экране должна скроллиться *внутри* панели.

### Фокус обратно

После закрытия фокус **возвращают на элемент, который открыл диалог**. Не всегда на `<html>`, не уничтожают, не на рекламный баннер.

Открыли Account с ссылки в шапке — закрыли, Tab снова на Account. Иначе фокус падает в начало страницы.

### Клик по оверлею

Это **распространённый UX, не всегда уместен для критичных форм**. Не требование HTTP, не нарушение HTML, не единственный способ закрыть.

Вход в Coral — можно закрыть кликом снаружи. Подтверждение «удалить заказ» — лучше только крестик и Escape, случайный клик мимо дорог.

### Анимация

Не должна **прятать фокус на 5 секунд без возможности закрыть**. Opacity и transform использовать можно. 200ms — нормальный интервал, не запрет.

```css
.modal {
  visibility: hidden;
  opacity: 0;
  pointer-events: none;
  transition: opacity 0.2s ease, visibility 0.2s ease;
}
```

`pointer-events` **управляет, кликабельна ли область**. Не HTTP-метод, не SQL, не кодировка. Пока модалка скрыта — `none`: клики проходят на каталог. Открыта — `auto`.

### Bottom sheet

Мобильный паттерн — **диалог, прижатый к низу экрана**. Не MIME-тип, не тег HTML6, не вид JOIN.

На узком экране карточку товара иногда выезжают снизу (`align-items: end`), а не центрируют. Смысл тот же: оверлей + панель + фокус.

**На тесте:** Escape, overflow hidden на body, фокус обратно, клик оверлея не всегда, анимация не прячет 5 сек, overflow auto на панели, pointer-events, bottom sheet.

## 4. `:target`, формы, несколько окон

На этапе 4 диалог открывается **без JS**. JS (этап 5) добавит фокус, ловушку и класс `modal_open`.

### `:target` по hash

Паттерн открывает диалог **по hash в URL без JS**. Не fetch, не SQL, не WebSocket.

```css
.modal_open,
.modal:target {
  visibility: visible;
  opacity: 1;
  pointer-events: auto;
}
```

Ссылка Account: `href="#modal-auth"`. Браузер находит элемент с этим id — срабатывает `:target`. Закрытие: `href="#"` (hash пустой, `:target` нет).

Открытие по якорной ссылке полезно **как прогрессивное улучшение без JS**. Не замена HTTPS, не единственный способ a11y, не кэш CDN.

Недостаток `:target` как единственного механизма — **слабый контроль фокуса и истории**. Не «не работает в HTML5», закрыть можно (ссылка на `#`), UTF-8 не ломает.

Каждое открытие пишет hash в историю: Back закрывает окно, но может увести со страницы. Фокус остаётся на ссылке Account, trap нет.

### Форма в диалоге

**Валидный и частый паттерн (логин).** Не запрещена, не только GET на другую вкладку, не только `prompt()`.

В `#modal-auth` — Sign in / Create account, поля с `label`, `type="email"` / `password`, `required`. Это та же форма, что на `login.html`, только в слое.

`type="button"` у крестика в форме нужен, **чтобы не сабмитить форму**. Не «включить CSS», не cookie, method не меняет.

В эталоне крестик — ссылка `<a href="#">`, не submit. Если сделаете `<button>` внутри `<form>` без `type="button"`, «закрыть» отправит логин (лекция HTML, вопрос про button без type).

### Скрытый в DOM vs удаление

**Оба подхода бывают; скрытый проще для a11y-связей.** Скрытый не всегда плох, удаление не запрещено, DOM умеет скрывать.

Coral держит обе модалки внизу `index.html` и переключает видимость. `aria-labelledby="auth-title"` не ломается: заголовок на месте. Удаление из DOM на закрытии потребует заново вешать id и обработчики.

Атрибут `hidden` в UA даёт по сути `display: none !important` и побеждает класс. Поэтому на этапе 4 скрытие — CSS `visibility` / `pointer-events`, не второй механизм `hidden`.

### Два диалога сразу

Нужна **очередь/стек, не два независимых trap без правил**. Не «всегда лучше», HTML это не требует, вкладки браузера не заменяет.

Account поверх карточки товара: какой Escape закрывает? Куда возвращать фокус? Обычно закрывают верхний, нижний остаётся, фокус — на триггер верхнего.

На этапе 4 в Coral два окна не открывают одновременно: одно `:target` на страницу.

### Кастом vs `confirm()`

Диалог подтверждения удаления лучше, чем `confirm()`, когда **нужен брендинг, пояснение, доступность**. Не когда любой ценой нужен синхронный блок потока JS. Не «нет CSS / нет HTML».

`confirm()` нельзя покрасить, нельзя добавить «Basic Dress Green, $236». Свой диалог — можно.

**На тесте:** :target по hash, слабый фокус и история, форма валидна, очередь двух диалогов, type=button, скрытый vs удаление, кастом vs confirm, якорь как progressive enhancement.

## Как отвечать на тесте

1. Отбросьте SQL, DNS, Docker, WebSocket, CORS, MIME — ловушки с других этапов.
2. Ищите **слой и фокус**: страница заблокирована, имя у крестика, Tab внутри, Escape закрывает, фокус возвращается.
3. Если вопрос про `:target` — это hash без JS и progressive enhancement, не единственный a11y-механизм.

После лекции: сверстать `#modal-auth` и `#modal-product` ([ДЗ этапа 4](../../04-modals.md)), открыть Account ссылкой без JS, проверить Tab и имя крестика, затем тест.
