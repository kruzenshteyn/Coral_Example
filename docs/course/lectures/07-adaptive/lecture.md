# Вводная лекция. Адаптивная вёрстка

Этап 7 курса. Тема теста: [Адаптивная вёрстка](../../tests/07-adaptive.md) — общие правила резины и брейкпоинтов, **не** про имена классов Coral.

Живые примеры к этой лекции: [examples.html](examples.html) (открыть в браузере).

Эталон этапа: `stage-07-adaptive/`.  
Как разложить CSS по блокам: [../../guides/07-adaptive.md](../../guides/07-adaptive.md).

---

## Зачем эта лекция

Макет Coral нарисован под широкий экран. Телефон не должен показывать ту же сетку из четырёх колонок: меню не влезет, фото героя высотой 560px раздавит экран 320px, кнопка «Shop now» окажется меньше пальца.

На этапе 7 эталон делает две вещи сразу:

1. каждый БЭМ-блок живёт в своей папке `css/blocks/*/`;
2. адаптив пишется **внутри блока**, desktop-first, пороги **1100 / 768 / 480**.

Бургер появляется на 768. Контейнер — `min(1320px, calc(100% - 40px))`. Карточки: 4 → 3 → 2 → 1 колонка.

На тесте правильный ответ почти всегда про **как ведёт себя layout**, а не про SQL, HTTP-статус и Photoshop.

## 1. Viewport и стратегия

### Мета viewport масштабирует layout

Мета viewport влияет на то, **как мобильный браузер масштабирует layout**. Не на HTTP-статус, не на SQL и не на цвет `:root` «обязательно».

Без мета-тега телефон рисует страницу как ~980px и уменьшает целиком: буквы мелкие, тап промахивается. С тегом ширина колонки = ширина экрана, брейкпоинты в `px` совпадают с тем, что вы задали.

### Типичная запись

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

`width=device-width` — ширина layout равна ширине устройства. `initial-scale=1` — без стартового зума. Не `width=1920` всегда, не пустой `content`, `user-scalable=0` не обязателен (часто вреден для доступности).

В Coral этот тег стоит уже с этапа 1. На этапе 7 от него зависят все `max-width`.

### Mobile-first vs desktop-first

**Mobile-first:** базовые стили для узкого экрана, усложнение в `min-width`. Не «только Android» и не запрет desktop.

**Desktop-first:** база под широкий экран, упрощение в `max-width`. Не «нельзя делать мобильную версию» и не «только print».

Макет Figma Coral — desktop. Идём **desktop-first**:

```css
.products__list {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
}

@media (max-width: 1100px) {
  .products__list { grid-template-columns: repeat(3, 1fr); }
}
@media (max-width: 768px) {
  .products__list { grid-template-columns: repeat(2, 1fr); }
}
@media (max-width: 480px) {
  .products__list { grid-template-columns: 1fr; }
}
```

### Breakpoint — порог

Это **порог ширины** (или другой media feature: `hover`, `orientation`). Не ошибка JS, не Git tag и не порт.

`@media (max-width: 768px)` срабатывает при ширине viewport **≤ 768px**. Не ≥ 768, не «только landscape».

Точка **768px** часто связана с **планшетом / крупным телефоном**: горизонтальное меню Coral уже не помещается, включают бургер. Не 4K TV и не часы.

### Нет mobile-фрейма — брейкпоинты всё равно в коде

Если в макете только Desktop 1920, адаптив **не незаконен** и не требует сайт `.m`. Пороги проектируют в коде, сверяя 1280 / 1024 / 768 / 375 в DevTools.

В Figma Coral как раз мало отдельных mobile-кадров. Этап 7 — про то, чтобы заложить сетку и бургер, а не ждать второй файл макета.

**На тесте:** viewport, типичная запись, mobile-first, desktop-first, breakpoint, `max-width: 768`, нет mobile-фрейма, смысл 768.

## 2. Резина: проценты, min(), clamp, wrap

### Fluid layout

Ширины в **`%` / `fr` / `min()`**, не только фиксированные px, не только таблица и не canvas.

```css
.products__list {
  display: grid;
  grid-template-columns: repeat(4, 1fr); /* колонки делят ряд */
  gap: var(--gap);
}
```

Карточка тянется вместе с колонкой. Жёсткие `width: 305px` на 375px дадут горизонтальный скролл.

### Адаптив vs отзывчивый

Часто: **адаптив — набор макетов** (отдельные компоновки на порогах), **отзывчивый — плавная резина**. На практике **смешивают**. Не синонимы RFC и не запрет.

Coral: резина (`fr`, `min()`, `clamp`) внутри, скачки сетки на 1100 / 768 / 480 — адаптивные макеты. Это нормально.

### `min()` для контейнера

Полезен, чтобы блок был **не шире родителя и не шире максимальной ширины**.

```css
.container {
  width: min(var(--container), calc(100% - 40px));
  margin-inline: auto;
}
```

`--container: 1320px`. На ультрашироком — потолок 1320. На узком — `100% - 40px` (по 20px с краёв). Не SQL `MIN` и не HTTP.

На 768 и 480 в Coral боковые поля сужают: `100% - 32px`, затем `100% - 24px`.

### Картинка `max-width: 100%`

**Не вылезает из колонки.** Не «всегда 100vw», не ломает `aspect-ratio` «всегда» и не отключает `src`.

```css
img {
  max-width: 100%;
  height: auto;
}
```

В карточке Coral картинку ещё ограничивают колонкой грида и `object-fit: cover`. Без `max-width: 100%` широкий JPEG вытолкнет сетку.

### `clamp(min, preferred, max)`

**Ограничивает значение между min и max.** Не только для цветов и не HTTP/3.

```css
.hero__content h1 {
  font-size: clamp(32px, 5vw, 67px);
}
```

На широком — 67px как в макете. На узком не мельче 32px. Посередине растёт с шириной экрана (`5vw`). Тот же приём для `padding` и ширины контейнера.

### `flex-wrap: wrap`

**Переносит элементы на следующую строку.** Не сжимает шрифт, не удаляет flex и не Grid area.

```css
.menu ul {
  display: flex;
  flex-wrap: wrap;
  justify-content: center;
  gap: 8px 28px;
}
```

Пункты меню Coral на среднем экране переносятся, пока на 768 меню не прячут в бургер. Без `wrap` ряд вылезет за край — горизонтальный скролл страницы.

**На тесте:** fluid, адаптив vs отзывчивый, `min()`, `max-width: 100%`, `clamp`, `flex-wrap`.

## 3. Картинки и единицы

### `srcset` / `sizes`

Подбирают **плотность и ширину картинки**. Не заменяют `alt`, не CSS Grid и не cookie.

```html
<img
  src="hero-800.jpg"
  srcset="hero-800.jpg 800w, hero-1600.jpg 1600w"
  sizes="(max-width: 768px) 100vw, 640px"
  alt="Woman in a brown wrap dress walking in the city"
/>
```

Телефон не качает 2400px. Экран 2x возьмёт более плотный файл. В Coral на учебных этапах часто один JPEG — на тесте спрашивают смысл атрибутов.

### `picture` + `source`

Разные файлы **под условия** (ширина, формат). Не замена `<img>` без fallback, не «только фон» и не SQL.

```html
<picture>
  <source type="image/webp" srcset="hero.webp" />
  <source media="(max-width: 768px)" srcset="hero-narrow.jpg" />
  <img src="hero-left.jpg" alt="…" />
</picture>
```

Без `<img>` внутри картинки не будет в старых браузерах. `source` выбирает файл, `img` — запасной и обязательный для a11y (`alt`).

### Фикс высота 560px на ширине 320

**Может обрезать и давить макет** — лучше адаптировать. Не «всегда идеально» и не замена `object-fit`.

В герое Coral на десктопе:

```css
.hero__gallery img {
  width: 100%;
  height: 560px;
  object-fit: cover;
}
```

На 320px два кадра по 560px — это больше двух экранов телефона. Поэтому:

```css
@media (max-width: 768px) {
  .hero__gallery img { height: 240px; }
}
@media (max-width: 480px) {
  .hero__gallery img { height: 220px; }
}
```

`object-fit: cover` обрезает кадр аккуратно, но высоту всё равно снижают.

### `vh` на мобильных

Бывает сюрприз из-за **скрытой панели браузера**. `100vh` часто больше видимой области: низ экрана прячется под панелью, потом «прыгает». Современные единицы: **`dvh` / `svh`**. Не «всегда равно % документа» и не px.

```css
.modal {
  min-height: 100vh;     /* может торчать под панелью */
  min-height: 100dvh;    /* динамическая видимая высота */
}
```

Для модалки на всю высоту на этапе 7 это важнее, чем для секции героя.

**На тесте:** `srcset`/`sizes`, фикс высота 560, `vh`/`dvh`, `picture`+`source`.

## 4. UX и сопровождение

### Бургер — когда меню не помещается

Появляется, когда **горизонтальное меню не помещается** / по макету mobile. Не «всегда на 4K», не отдельный тег HTML и не «без JS невозможно концептуально» (можно checkbox-хак, но в Coral — кнопка + класс).

```css
.burger { display: none; }

@media (max-width: 768px) {
  .burger { display: block; }
  .menu { display: none; }
  .menu.is-open { display: block; }
}
```

JS на этапе 5 уже переключает `is-open`. На этапе 7 бургер **виден** только ≤768.

### Hover на таче ненадёжен

Важные действия **не прячут только в hover**. Hover не работает «как мышь всегда» и не заменяет click.

В карточке Coral «View product» на десктопе всплывает при наведении. На 768 его показывают всегда:

```css
@media (max-width: 768px) {
  .product-card__hover {
    opacity: 1;
    transform: none;
  }
}
```

Цена, бейдж Sale, ссылка на товар — видимы без наведения. Hover-подсказка не единственный способ открыть карточку.

### Зона нажатия 44–48px

Ориентир минимального размера — **около 44–48px**. Не 1px, не «обязательно 200» и не «нигде не нормируется даже как UX-совет» (Apple HIG ~44, Material ~48).

Пункт выезжающего меню Coral: `padding: 10px 0` при кегле 15px даёт высоту около 44px. Иконка бургера — `padding: 6px` плюс кегль 22px. Мелкий крестик 16×16 без поля — промах пальцем.

### `overflow-x: auto` на таблице

Иногда **спасает таблицу**, но лучше перестроить layout. Не единственно правильный адаптив и не «включает JS».

Узкая колонка + широкая таблица состава заказа: горизонтальный скролл **внутри** таблицы. Горизонтальный скролл **всей страницы** — уже баг.

```css
.table-wrap { overflow-x: auto; }
```

Каталог карточек так не спасают: его перестраивают в одну колонку.

### Orientation

Landscape **можно учесть в media query**. Не «нельзя в CSS» и не «только JS API».

```css
@media (orientation: landscape) and (max-height: 500px) {
  .hero__gallery img { height: 160px; }
}
```

Телефон на боку: высокий герой съедает экран. Это дополнение к ширине, не замена 768.

### `@container`

Реагируют на **ширину контейнера**, не только viewport. Не запрещены и не HTML-атрибут.

Карточка в сайдбаре 300px и та же карточка в сетке 900px при одном viewport ведут себя по-разному. Для этого `container-type: inline-size` на родителе и `@container (max-width: 400px)`. В Coral этап 7 опирается на viewport — на тесте спрашивают идею.

### `font-size: 8px`

На мобильном **плохо читается**. Не требование a11y (наоборот), не ускоряет сеть и не SEO.

Кегль тела Coral — 16px, категории — 14px, подписи — не мельче. 8px «чтобы влезло» ломает и зрение, и тап по тексту-ссылке.

### `display: none` vs визуально скрыть

`display: none` **убирает из раскладки и обычно из a11y-дерева**. Не то же самое, что visually-hidden (позиция за экраном, для скринридера жив). HTML `hidden` существует; CSS скрывать умеет.

Бургер прячет `.menu` через `display: none` — пункта нет ни в сетке, ни в фокус-порядке, пока нет `.is-open`. Иконка с видимой подписью так не прячут.

### `prefers-reduced-motion`

**Уменьшает анимации** для чувствительных пользователей. Не «ускоряет CPU всегда» и не отключает картинки.

```css
@media (prefers-reduced-motion: reduce) {
  .product-card__hover {
    transition: none;
  }
}
```

Ховер-плашка Coral едет `0.2s ease`. При системной настройке «уменьшить движение» переход убирают.

### Тестировать ресайзом, не только 1920

Нужно **ресайзом и на реальных ширинах**, не только скрин макета, не только 1920, не только Photoshop и не только Lighthouse SEO.

Проверка этапа 7: DevTools 1280, 1024, 768, 375. Клик по бургеру, открытие карточки, форма входа. Между порогами тоже смотрят: баг часто на 769 и на 1101.

### Горизонтальный скролл на 375px

Обычно **баг**: элемент шире 100% (фиксированная ширина, отрицательный margin, `100vw` + скроллбар, картинка без `max-width`). Не требование HTML5 и не a11y.

Ищут виновника в DevTools: Outline / `overflow`. Часто это герой, баннер или ряд брендов без `wrap`.

### Медиа в файле блока

Адаптив «в файле блока», а не кучей в конце — **проще сопровождать компонент**. Браузер применит `@media` и из общего файла; спецификация не запрещает ни тот, ни другой способ; каскад «ломается не всегда».

```text
css/
  index.css                 ← только @import
  blocks/
    products/products.css   ← сетка 4→3→2→1
    burger/burger.css       ← display на 768
    hero/hero.css           ← высота фото, clamp заголовка
    menu/menu.css           ← колонка на 768
```

Правите карточку — открываете `product-card.css`, а не ищете «тот самый @media» в 2000 строках. ДЗ этапа 7: вынести блок в свою папку с собственными 768 и 480.

**На тесте:** бургер, hover, 44–48px, overflow таблицы, orientation, `@container`, 8px, `display: none`, reduced-motion, ресайз, гориз. скролл, медиа в блоке.

## Как отвечать на тесте

1. Отбросьте SQL, HTTP-статус, Git, Photoshop как единственную проверку — ловушки с других этапов.
2. Ищите **что происходит с layout**: порог `max-width`, резина vs фикс px, что видно пальцу без hover.
3. Если вопрос про единицу или функцию CSS (`min()`, `clamp`, `vh`, `srcset`) — зачем её взяли на узком экране, не «как называется свойство в Figma».

После лекции: открыть `stage-07-adaptive/` (для JSON — локальный сервер, как на этапе 5), пройти 1280 / 1024 / 768 / 375, кликнуть бургер, сверить медиа в `css/blocks/*/`. Затем ДЗ ([этап 7](../../07-adaptive.md)) и тест.
