Вопросы 7, 22

Композиция: Catalog имеет карточки

Связь «имеет», не «является». Каталог — сервис загрузки и отрисовки, не вид списка: его не наследуют от Array.

Имеет

  • Catalog
    • items: Product[]
    • load() / render()
    • рисует ProductCard
  • UserSession имеет StorageBox

Не является

class Catalog extends Array {
  // push, map, length — не смысл каталога
}

У Coral у каталога есть URL JSON, два корня DOM и findById. Это не массив.

Вопросы 8, 15, 19, 20, 23, 24, 27, 29, 30

Фасад App, не божественный объект

SRP — одна задача на класс. App прячет сборку. Конструктор не делает fetch: это start(). Рефакторинг успешен, если поведение то же, читать проще.

Фасад

App
 ├─ Catalog ── Product ── ProductCard
 ├─ UserSession ── StorageBox
 ├─ Selection ── StorageBox
 ├─ AuthModal ── Modal
 └─ ProductModal ── Modal

HTML знает одну точку входа. Публичный интерфейс: load, open, login.

Божество и coupling

Один класс на 2000 строк: fetch, localStorage, Esc, валидация, бургер. Высокая связность — если A лезет в b.signinForm вместо b.open().

FormValidator.isEmail тестируется без DOM. Конструктор App только собирает поля, сеть — в start().
