# Вводная лекция. БЭМ: независимые блоки

Этап 3 курса. Тема теста: [БЭМ](../../tests/03-bem.md) — методология имён, **не** про дословный список классов Coral.

Живые примеры к этой лекции: [examples.html](examples.html) (открыть в браузере).

Эталон этапа: `stage-03-bem/`.  
Как переименовать этап 2: [../../guides/03-bem.md](../../guides/03-bem.md).

---

## Зачем эта лекция

На этапе 2 классы простые: `.header-top`, `.product-card-media`, `.badge-sale`. Пока страница одна — работает. Как только карточку вынимают в модалку, а меню переносят в бургер, селектор `.products .item a` ломается: он ждал конкретного родителя.

БЭМ даёт **предсказуемые имена** и **слабую связанность с DOM**. Визуал Coral на этапе 3 тот же, что на этапе 2. Меняются только классы.

На тесте правильный ответ почти всегда про **независимость блока и правило имени**, а не про SQL, DNS, Docker и Wi‑Fi.

---

## 1. Имена: блок, элемент, модификатор

**БЭМ** расшифровывается как **Блок, Элемент, Модификатор**. Не «браузер / модуль», не Bundle Export Minify.

На курсе классика bem.info: `block__elem`, `block_mod` (одно подчёркивание). Суффикс `block--mod` тоже встречается в мире — здесь **один** стиль, без смеси.

### Блок

**Независимый компонент интерфейса.** Не любой HTML-тег, не «только `div`», не HTTP-маршрут.

```html
<header class="header">…</header>
<article class="product-card">…</article>
<form class="search-form">…</form>
```

Карточка товара — блок: её можно вырезать из сетки и вставить в модалку. Шапка — блок. Кнопка `.btn` — блок.

Имя блока пишут **строчными, слова через дефис**: `search-form`. Не CamelCase, не `__form` с подчёркивания в начале, не кириллицей.

### Элемент

**Принадлежит конкретному блоку**, не всему документу, не модификатору и не CSS-переменной.

Классическое имя: **`menu__item`** — два подчёркивания между блоком и элементом.

```html
<nav class="menu">
  <ul>
    <li class="menu__item"><a class="menu__link" href="#products">Jewelry</a></li>
  </ul>
</nav>
```

`menu__item` без блока `menu` не существует. Не пишут `menu-item-element`, не `Menu.Item`.

Модификатор элемента: **`list__item_active`** (элемент, затем одно `_` и имя модификатора). Не `list_item__active` и не `item.list.active`.

```html
<p class="product-card__badge product-card__badge_type_sale">Sale</p>
```

### Модификатор

Меняет **внешний вид или состояние** блока или элемента. Не doctype, не DNS, не порт сервера.

Пример модификатора блока: **`button_disabled`**. Не `button__disabled__true` (это как будто элемент), не `.button disabled` (класс + атрибут вперемешку).

```html
<article class="product-card product-card_selected">
  <p class="product-card__badge product-card__badge_type_sale">Sale</p>
</article>
```

В Coral: `product-card_selected` — выбранная карточка (обводка primary). `product-card__badge_type_sale` — тип бейджа.

### Два модификатора

**Допустимы двумя классами.** HTML это не запрещает. Не обязателен один класс «со всеми словами», не через id.

```html
<button class="btn btn_size_l btn_disabled" type="submit">Sign in</button>
```

Два класса: размер и состояние. В CSS — два правила, каждое с весом одного class.

**На тесте:** расшифровка, блок, элемент, `menu__item`, модификатор, `button_disabled`, `search-form`, `list__item_active`, два модификатора двумя классами.

## 2. Независимость и селекторы

Смысл методологии не в «красивых подчёркиваниях», а в том, что **блок живёт без конкретного родителя**.

### Почему не `.header nav ul li a`

**Высокая связанность с DOM, хрупко при смене вёрстки.** Браузер такой селектор понимает. Он не быстрее БЭМ и HTML5 его не запрещает — просто завтра список станет `ol` или ссылку обернут в `div`, и стиль пропадёт.

```css
/* плохо: три обёртки обязательны */
.header nav ul li a { color: #1e2832; }

/* хорошо: элемент или блок ссылки */
.menu__link { color: #1e2832; }
```

### Стили без конкретного родителя

Независимость блока значит: **стили не должны требовать конкретного родителя**. Блок можно повторить. Модификатор задавать можно. CSS использовать можно — как раз им и рисуют блок.

```css
.product-card { position: relative; }
.product-card__media img {
  width: 100%;
  height: 320px;
  object-fit: cover;
}
```

Нет `.products .product-card`. Карточка в футере, в модалке, в «related» выглядит так же.

Стили элемента **не должны зависеть от того, что снаружи блока** (по возможности). Модификатор своего блока, переменные `:root` и каскад *внутри* блока — нормальны.

```css
/* хрупко: элемент ждёт, что карточка в секции products */
.products .product-card__price { font-size: 18px; }

/* лучше: модификатор самой карточки */
.product-card_size_l .product-card__price { font-size: 18px; }
```

### Не `div.card`

Тег в селекторе **снижает переносимость, лучше `.card`**. Не обязателен, не «ускоряет отрисовку в разы», для a11y не нужен.

Карточка Coral — `<article class="product-card">`. Если написать `div.product-card`, статья не получит стилей. Блок привязан к тегу зря.

### Ложный БЭМ

Это когда **имена как БЭМ, но стили завязаны на вложенность тегов**. Наличие модификатора, элемента или файла с именем блока само по себе ложный БЭМ не отменяет.

```css
.product-card article div span { color: #8f9499; } /* имена БЭМ снаружи, внутри — суп */
```

### Специфичность одного класса

Один класс БЭМ весит **как один class-селектор**. Не как id, не как `!important`, не ноль.

`.product-card__media` и `.btn` — одинаковый вес (0, 1, 0). Поэтому каскад предсказуем: спорят только порядком в файле и модификаторами, не «длиной имени».

**На тесте:** длинный селектор, независимость от родителя, не `div.card`, ложный БЭМ, элемент не от снаружи, специфичность одного class.

## 3. Структура: микс, вложенность, файлы

БЭМ описывает **роли на узле**, а не запрещает HTML-дерево. Блоки вкладывают. Элемент элемента — нет.

### Микс

**Несколько классов на одном узле** (блок + элемент другого блока). Не слияние Git, не обязательный Sass `@mixin`, не iframe.

```html
<div class="container header__top">
  <!-- контейнер (блок страницы) + элемент шапки -->
</div>
```

В Coral шапка: `class="container header__top"`. Узел одновременно ограничивает ширину 1320px и раскладывает поиск / лого / Account.

### Не `block__el__sub`

Элемент элемента **не рекомендуют**: делают новый блок или элемент исходного блока. Это не обязательный паттерн и не замена модификатора.

```html
<!-- плохо -->
<li class="menu__list__item">…

<!-- хорошо: элемент блока menu -->
<li class="menu__item">…

<!-- или новый блок, если кусок переиспользуется -->
<form class="search-form">…</form>
```

`header__top-nav-item` уже пахнет цепочкой. Если навигация сложная — блок `menu` внутри `header`.

### Блок содержит другие блоки

**Можно.** Не «только текст», не «только один элемент», не «модификаторы без DOM».

```text
header
├── search-form          ← другой блок
├── logo
└── user-nav             ← другой блок
product-card
├── product-card__media  ← элемент
└── product-card__badge  ← элемент (модификатор type_sale)
```

Шапка Coral содержит `search-form`. Каталог содержит много `product-card`. Модалка на этапе 4 содержит форму и карточку.

### Модификатор не переименовывает элементы

Смена модификатора **не должна требовать переименовать все элементы**. Вид менять как раз должна. Отдельный класс — да. CSS — да.

```html
<article class="product-card product-card_selected">
  <a class="product-card__media" href="product.html">…</a>
  <h3 class="product-card__title">…</h3>
</article>
```

Включили `_selected` — `product-card__media` остался `product-card__media`. Иначе каждый вариант UI — новое дерево имён.

### Файл на блок

Удобен, потому что **проще найти и удалить неиспользуемое**. Браузер применит CSS и из одного `style.css`. HTML не требует 1:1. Это не единственный способ каскада.

На этапе 3 в эталоне ещё один файл — проще для курса. На этапе 7 появятся `css/blocks/product-card.css`. Сейчас важно *правило*: один блок — одно место правки.

### Переиспользуемый кусок

Если UI встречается в трёх местах — **это кандидат в отдельный блок**. Не копируют три уникальных БЭМ-дерева, не iframe, не canvas.

Кнопка «Shop now» в герое и в баннере Zara — один `.btn`. Карточка в каталоге и позже в модалке — один `product-card`.

**На тесте:** микс, не `block__el__sub`, файл на блок, блок содержит блоки, модификатор не переименовывает элементы, переиспользуемый кусок = блок.

## 4. Практика: семантика, состояния, команда

Методология не заменяет HTML и здравый смысл. Сначала страница должна работать, потом имена становятся договором команды.

### «Открыто» — модификатор

Состояние логично делать **модификатором**, не новым типом элемента, не новым doctype и не только inline style.

```html
<nav class="menu menu_open">…</nav>
<div class="modal modal_open">…</div>
```

На этапе 4 CSS уже знает `.modal_open`. Этап 5 только вешает класс. JS не пишет `style.display`.

`.is-open` без пространства блока — **состояние-утилита; в строгом БЭМ чаще `menu_open`**. Это не обязательный элемент, не модификатор элемента `menu` само по себе и не невалидный HTML.

### БЭМ не отменяет семантику

**Семантические HTML-теги остаются.** Не отменяет HTML вообще, не HTTP, не UTF-8.

```html
<article class="product-card">          <!-- смысл: товар -->
  <h3 class="product-card__title">…</h3>
  <a class="product-card__media" href="product.html">…</a>
</article>
```

Класс не превращает `div` в статью. Скринридер читает тег.

### `btn` на `<a>` и `<button>`

**Один блок `btn`, разные теги.** Не «нельзя», не разные методологии, не всегда `<div role="button">`.

| В Coral | Тег | Классы |
| --- | --- | --- |
| Shop now → каталог | `<a>` | `btn` |
| Submit рассылки | `<button type="submit">` | `btn` |
| Позже: закрыть модалку | `<button type="button">` | `modal__close` |

Вид общий, смысл разный — как на лекции HTML.

### Длинное имя `header-top-nav-item-link-text`

**Скорее не БЭМ, а цепочка смыслов в одном классе.** Не идеальный элемент, не модификатор, не микс.

Правильный путь: блок `header`, внутри блок `menu`, элемент `menu__link`. Каждый кусок отвечает за своё.

### Утилиты отступов — осторожно

Одинаковые отступы выносят в утилиту **чтобы не плодить модификаторы «чуть левее»**. HTML утилиты не запрещает, CSS умеет margin, UTF-8 не ломается.

```css
.container { width: min(1320px, calc(100% - 40px)); }
```

`container` на курсе — общий ограничитель ширины, микс к шапке и секциям. Десять классов `u-mt-12 u-ml-7` на каждой карточке — уже не БЭМ-независимость, а набор исключений.

### Документация блока

Обычно описывает **элементы, модификаторы, примеры HTML**. Не только SQL, не Docker, не пароли.

```text
product-card
  элементы: media, title, category, price, badge, hover
  модификаторы: _selected
  badge_type_sale, badge_type_hot
```

Студент на приёмке этапа 3 должен устно разобрать шапку: что блок, что элемент, что модификатор.

### Сначала вид, потом БЭМ

Рефакторинг «классы как попало → БЭМ» — **нормальный учебный путь: сначала вид, потом методология**. Не невозможен, HTML5 не ломает, валидатор не запрещает.

Этап 2 → этап 3 в Coral ровно такой: скопировали папку, составили таблицу `header-top` → `header__top`, меняли HTML и CSS парами.

### Зачем это команде

Главная цель — **предсказуемые имена и меньше конфликтов стилей**. Не ускорить Wi‑Fi, не заменить Git, CSS не шифрует.

Два человека могут править `product-card` и `footer` параллельно: селекторы не пересекаются. Новый бейдж — модификатор, а не `.products ul li:nth-child(4) span`.

**На тесте:** открыто = модификатор, семантика, btn на a и button, длинное имя, утилиты осторожно, документация, сначала вид, `.is-open` vs `menu_open`, меньше конфликтов.

## Как отвечать на тесте

1. Отбросьте SQL, DNS, Docker, Git merge, Wi‑Fi — ловушки «из другого этапа».
2. Ищите **роль имени**: блок независим, элемент принадлежит блоку, модификатор меняет вид/состояние.
3. Если показывают длинный селектор или `header-top-nav-item-link-text` — это связанность с DOM, не БЭМ.

После лекции: переименовать этап 2 по таблице ([ДЗ этапа 3](../../03-bem.md)), проверить независимость карточки (вырезать в футер), затем тест.
