Вопросы 1, 2, 17, 28

Методы: GET, POST, идемпотентность, PUT / PATCH

GET — чтение без побочек. POST — действие с телом. PUT заменяет целиком, PATCH — частично. Повтор PUT/DELETE даёт тот же эффект.

GET — каталог

GET /api/products

200 { "ok": true, "data": [ … ] }

Можно повторять и кэшировать. В Coral так грузят товары. Query ?q=hat — тоже GET (вопрос 24).

POST — вход и заказ

POST /api/auth/login
Content-Type: application/json

{"email":"ada@coral.test","password":"secret1"}

Тело обязательно для логина. Повтор POST регистрации с тем же email — уже 409, не «ещё один пользователь».

Идемпотентность и PUT vs PATCH

PUT   /api/users/3   { "name": "Ada", "email": "ada@coral.test" }
PATCH /api/users/3   { "name": "Ada Lovelace" }

DELETE /api/orders/12   ← второй раз: ресурс уже нет, эффект тот же

Coral заказы добавляет POST (не идемпотентен). PUT — полная замена, PATCH — поля. GET безопасен и идемпотентен.

Вопросы 11, 12, 18, 19, 24, 25, 29, 30

Контракт: три стека, маршруты, статика, healthcheck

Ресурсы — существительные /users, /products. PHP, Django и Node сравнимы, потому что все принимают HTTP и отдают JSON.

:8000

PHP

php -S localhost:8000 router.php

:8001

Django

python manage.py runserver 8001

:8002

Node.js

npm start

Один фронт frontend/ · один контракт { ok, data } / { ok, error }

Маршрут = method + path

GET  /api/products
GET  /api/products/:id
POST /api/auth/register
POST /api/auth/login
GET  /api/me          ← сессия
POST /api/orders      ← { productId }
GET  /api/products?q=hat

Статику роутер отдаёт по пути из ФС с Content-Type: style.css → text/css.

Таймаут и healthcheck

GET /health  →  200 { "ok": true }
// лёгкий GET: процесс жив, не логин и не список товаров

const ctrl = new AbortController();
setTimeout(() => ctrl.abort(), 8000);
fetch(url, { signal: ctrl.signal });

Таймаут прерывает слишком долгое ожидание. Healthcheck должен отвечать быстро.

Вопросы 13–16, 20–23, 26, 27

Сессии: HttpOnly, CORS, CSRF, same-origin

Сессия хранит id пользователя. Cookie ставит сервер заголовком Set-Cookie. Пароль — хеш с солью, в JSON и в логах его нет.

HttpOnly vs localStorage

// этап 5 — видно JS, XSS украдёт
localStorage.setItem("coral-user", …)
document.cookie // сессию не читает, если HttpOnly

// этап 6 — Set-Cookie от сервера
Set-Cookie: PHPSESSID=abc; HttpOnly
fetch("/api/me", { credentials: "include" })

Same-origin = схема + хост + порт. localhost:8000 и :8001 — разные origin.

CORS: origin A → origin B

A · страница

http://localhost:8080

JS делает fetch

→
B · API

http://localhost:8000

нужен Access-Control-Allow-Origin

В Coral PHP сам отдаёт фронт — запросы same-origin, CORS не нужен. Сервер → БД CORS не касается.

1. Вы на Coral

Залогинены, браузер хранит сессионную cookie.

3. Заказ «от вас»
