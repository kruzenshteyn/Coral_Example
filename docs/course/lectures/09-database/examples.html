Вопросы 1, 2, 3, 4, 5, 6

Таблица, строка, PK, FK, UNIQUE, NULL

Таблица — строки с одинаковыми столбцами. Строка — одна запись. Фиолетовый столбец — PRIMARY KEY. Подчёркнутый — FOREIGN KEY.

users

id PK name TEXT email UNIQUE is_admin INTEGER
1 Admin admin@coral.local 1
2 Ada ada@coral.local 0

Сид: admin@coral.local / admin123. UNIQUE не даст второго такого email.

selected_products.user_id → users.id  ·  selected_products.product_id → products.id

products

id PK title price REAL old_price
joggers Adicolor Classics Joggers 63.85 NULL
nike-bag Nike Sportswear Futura Luxe 130 NULL
hoodie Yellow Reserved Hoodie 155 364

NULL ≠ 0 ≠ ''. У Joggers скидки нет, у Hoodie — есть старая цена.

selected_products

id user_id FK product_id FK
10 2 joggers
11 2 nike-bag

Связь «Ada выбрала joggers». Не копия email и не цена витрины.

INTEGER · TEXT · REAL

INTEGER 1 TEXT admin@coral.local REAL 63.85 

id INTEGER PRIMARY KEY AUTOINCREMENT
email TEXT NOT NULL UNIQUE
price REAL NOT NULL
old_price REAL          -- NULL, не 0

REAL — float, не банковский decimal «всегда». Картинка — TEXT с путём, не файл ОС в столбце. Новые id пользователей выдаёт база.

ORM — объекты ↔ таблицы. Миграция версионирует схему. Индекс на email ускоряет логин, INSERT становится чуть дороже.
